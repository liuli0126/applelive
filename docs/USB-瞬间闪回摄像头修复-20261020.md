# USB 直播短暂闪回手机摄像头

用户确认：USB 直连时，手机预览和观众端都会短暂看到手机原始摄像头，然后恢复推流画面。

## 已定位的代码路径

1. 原 `ALFrameStore` 在 USB 接收超过 0.75 秒没有新帧时返回空图像。USB 重连和解码重建的回调也会清空上一帧。
2. 画面替换返回空或渲染失败时，AVCapture delegate 和 BW hooks 会继续把原始摄像头帧传给直播 App。
3. 手机预览在一次取帧失败时隐藏叠加层并删除当前图像，进一步露出下面的相机预览。

这解释了“闪一下真实摄像头”的路径。某个客户触发接收间隔的具体原因仍需该设备日志区分，可能涉及等待关键帧、传输重连或渲染失败；不能仅凭这个症状认定电脑驱动损坏。

## 修复行为

- 保留最新一帧，直到新有效画面到达或用户主动切换/停止来源。只有一个帧缓存，不增加播放队列或固定延迟。
- 自动重连只标记接收中断并清理解码/音频状态，保留显示图像。接收是否新鲜使用单调时钟，保留图像不会被当作仍在正常接收。
- 启用替换期间，替换失败的原始视频帧不再转发给直播 App；已经替换的帧和原有音频通道正常通过。
- 预览取帧失败、暂时无法入队或相机会话重启时保留当前图像。切换来源和“恢复手机相机”仍清理旧画面。
- 新日志记录接收间隔后的恢复和重连时保留画面的事件，便于后续查明具体设备的中断原因。

## 安装和手机验收

1. 把上述 `福煋推流插件.dylib` 传到手机，使用原注入器替换目标直播 App 内的旧插件，避免同时注入两份同类插件。
2. 完全退出目标 App 后重新打开，继续使用原来的 USB 直连设置。电脑端不需要重新安装。
3. 在原受影响手机上进行长时间 USB 直播，同时观察手机和观众端、检查内录声音。短暂断流时应保留上一帧，恢复后继续；主动恢复手机相机应正常切回。

当前完成的是自动回归、编译和文件交付；没有在用户手机上安装或重启 App，也没有完成该手机的长时间直播验收。修复阻断了已定位的摄像头泄露路径，但不能凭自动测试承诺所有设备和直播 App 永不闪动。后续如仍出现停顿，需要导出发生时的手机/电脑日志定位原始中断原因。
