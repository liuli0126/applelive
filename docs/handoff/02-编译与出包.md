# 编译与出包

## Windows电脑端

准备：Windows x64、Visual Studio 2022 C++构建工具和Windows SDK、CMake、Python。CI使用Python3.12，原生ABI基线为OBS30.2.3。需要执行界面测试时另外准备Node.js和Python的psutil。

将单独提供的 `福煋OBS.zip` 解压到例如 `D:\福煋OBS`；这是编译/测试所需宿主，不要选正在运行的客户目录来覆盖测试。源码包保留目录结构并在源包根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r desktop_sender/requirements.txt pyinstaller psutil
$ObsRoot = 'D:\福煋OBS'
$env:PATH = (Resolve-Path '.\obs-plugin').Path + ';' + $env:PATH
```

在 **Visual Studio Developer PowerShell（x64）** 中激活同一Python环境，然后运行：

```powershell
.\scripts\build-native-windows.ps1 -ObsRoot $ObsRoot
.\scripts\build-obs-plugin.ps1 -PhonePlugin '.\obs-plugin\phone-plugin\AppleLive.dylib'
.\scripts\build-portable-obs.ps1 -ObsRoot $ObsRoot -Output '.\交付文件\福煋OBS.zip'
```

`build-native-windows.ps1` 通过目标OBS的导出表生成导入库，并编译启动器、原生输出DLL和USB中继。`build-obs-plugin.ps1` 用PyInstaller编译面板服务/兼容发送器，依赖 `ffmpeg.exe` 能在PATH中找到；它也需要 `obs-plugin/server/mediamtx.exe`。以上依赖与当前参考产物已随源码包提供。

不要在改动原生源码后仅执行Python打包脚本，否则可能把上一次DLL装入新包。完整客户包应使用第三步生成，不能把源码目录当成客户运行目录。

## 手机端：没有Mac时

1. 将本源码目录上传到同事的GitHub仓库，包含 `.github/workflows` 和品牌资源。无需迁移原作者账号密码。
2. 在Actions启用并运行 **Build AppleLive injector dylib**（`build-ios-injector.yml`）。
3. 该流程在macos-14中准备Theos、SDK、FFmpeg、fishhook、UVC依赖，并执行相关媒体测试后构建。
4. 下载产物 **AppleLive-Injector-iOS14**；这是历史产物名，不代表仅支持iOS14。
5. 使用其中的 `AppleLive.dylib`、`AppleLive-relink.tar.gz`、许可证和可选服务产物更新 `obs-plugin/phone-plugin/`。
6. 执行 `python scripts/verify-injector-dylib.py obs-plugin/phone-plugin/AppleLive.dylib`，再进行手机实测和电脑整包打包。

Windows云端任务 **Build AppleLive OBS plugin** 可自动依赖手机构建，也可填写同一仓库已成功的 `phone_run_id`。该任务生成插件包；包含OBS本体的客户整包仍由 `build-portable-obs.ps1` 生成。

## 手机端：本地Mac

Theos、iPhoneOS16.5 SDK、ldid、dpkg及GNU make等准备方式，以 `build-ios-injector.yml` 中步骤为准。依次执行该工作流中的USB Host依赖编译、FFmpeg编译、fishhook准备、测试和dylib构建步骤，避免遗漏静态库或签名。

工作流分别编译：

```bash
make -C ios-injector all FINALPACKAGE=1 ARCHS=arm64 TARGET=iphone:clang:16.5:14.0
# 保存arm64产物后clean，再编译arm64e：
make -C ios-injector clean
make -C ios-injector all FINALPACKAGE=1 ARCHS=arm64e TARGET=iphone:clang:16.5:15.0
```

然后按工作流用 `xcrun lipo -create` 合并两份产物，执行 `ldid -S`。直接使用Makefile默认值会为两种架构使用iOS15.0目标；需要保持现有产物的部署目标时，以工作流分别编译的命令为准。

`AppleLive-relink.tar.gz` 包含已编译对象、FFmpeg/UVC静态库、对应依赖源码和重链接脚本，可在Mac上使用；修改项目源代码后仍需重新编译对应对象，不能仅运行重链接脚本就认为新源代码已生效。

## 依赖基线

| 组件 | 当前源码/流程使用的基线 |
|---|---|
| OBS ABI | 30.2.3 x64 |
| MediaMTX | v1.18.1（Windows工作流固定下载和SHA256） |
| 手机FFmpeg | n6.1.2；脚本校验固定提交 |
| fishhook | aadc161ac3b80db07a9908851839a17ba63a9eb1 |
| libusb/libuvc | 固定提交见 `scripts/build-ios-uvc.sh` |
| Theos、SDK、ldid | 工作流安装；Theos/SDK克隆未固定提交 |
| Python依赖 | `desktop_sender/requirements.txt` 范围约束 |

现有工作流不是完全锁定依赖的可重现构建；新构建通过测试后还需比较版本/架构和实机表现，不能承诺产物SHA256必然和参考文件一致。

本地工作目录中的私有配置信息无需交给同事。测试机的苹果驱动、手机越狱/注入环境由实际设备配置；Windows源码编译不需要Apple账号密码。
