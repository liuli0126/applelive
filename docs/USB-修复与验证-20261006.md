# AppleLive USB 直连修复记录

目标环境：iPhone 11、iOS 15.6、抖音，电脑使用配套的 OBS 30.2.3。

## 对 SkyCam 的研究结论

对用户提供的 `SkyCam/Sky.dylib` 与 `SkyCam/Cam.dylib` 进行了离线 Mach-O 分析。`Cam.dylib` 的类、系统库导入和日志包含 USB 接收、VideoToolbox 视频解码、AudioConverter AAC 解码、关键帧等待、序号缺口检测、解码器重建和积压处理。`Sky.dylib` 有界面与控制相关线索，没有发现 VideoToolbox 解码导入。

这些是静态证据，不能据此认定已恢复同行全部源码、协议或证明其不会崩溃。本次根据这些机制修复我们自己的实现。

## 已修复的问题

| 问题 | 本次处理 |
| --- | --- |
| 新原生中继把手机握手发送方向写反 | 先读取手机的 `ALUSB1`，确认后才允许电脑开始送帧 |
| OBS 接口结构声明与真实布局不符，缺少模块导出与输出回调 | 对照 OBS 30.2.3 官方头文件修正，使用真实 libobs 加载和编码测试 |
| 错误释放 OBS 借出的编码包 | 仅复制数据；包的释放仍由 OBS 执行 |
| 音频包可能提前解除视频关键帧等待 | 仅带参数集的 IDR 可以解除等待；重连及队列溢出重发音频配置 |
| 旧发送端把同一画面的多个分片分开发送 | 聚合成完整 H.264 画面后再送往手机 |
| 手机在缺帧或解码错误后继续解码依赖旧画面的帧 | 重建解码会话，等待下一个关键帧恢复 |
| AAC 解码与断开连接并发操作解码器 | 同步解码和释放，使用系统 AudioConverter 处理 AAC-LC |
| 新手机音频配置与旧交付 dylib 不匹配 | 重新编译手机 arm64/arm64e，并与电脑端一起交付 |
| 新电脑初次启动没有场景可注册脚本 | 完整包创建默认场景和配置，预置停靠面板和脚本 |

USB 路径：OBS 独立编码输出 → 本机 USB 中继 → 苹果 usbmux 驱动 → 手机插件。点击“准备 USB 直连”即可准备，无须 OBS“开始直播”。LAN 仍使用独立的 RTMP/RTSP 路径。

## 已完成验证

- 实际运行 Windows 原生中继的四项测试通过：XML/binary 回复、USB 设备筛选、精确转发、重连、错误握手及缺失连接结果的拒绝、中文状态文件路径。
- 在真实 OBS 30.2.3 内核加载新 DLL，连续三次连接各录得 65 个完整视频帧、1 个 AAC 配置包及 100 个 AAC 数据包；重复启动、停止和再启动通过。录下的视频通过 FFmpeg 解码检查。
- GitHub macOS runner 使用手机共用的解码代码，实际解码 OBS 录制的数据与多分片样本。视频、AAC 音频、丢帧等待关键帧、解码中断开、重连测试通过。
- 同一手机构建的源设置、媒体、色彩、RTMP/RTSP 检查通过；arm64 与 arm64e 构建、独立 dylib 检查通过。
- 电脑协议、停靠面板、USB 发送、连接模式与 OBS 控制的现有回归检查通过。

手机源码与构建来自提交 `3b5dcaf`，成功的构建任务为 `37399330392` 的 `build-phone-plugin / build-injector`。另一个同提交独立构建遇到 RTMP 测试启动采样窗口不足，已将测试拆为有上限的启动等待与连续播放验证，保留原有帧数要求。
