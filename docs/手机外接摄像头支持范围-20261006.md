# 手机外接摄像头：接入条件与实现边界

目标是在 AppleLive 手机悬浮窗中切换到物理连接手机的摄像头或采集卡。目标设备为 iPhone 11，希望兼容多个品牌；用户最新实机诊断显示系统为 iOS 15.4.1（19E258），与之前口述的 15.6 不同。

## 已确认的限制

品牌本身不是兼容条件，视频协议、手机驱动、转接方式和供电才是。普通 USB 摄像头及许多 HDMI 采集卡使用 UVC；部分面向 iPhone 的设备使用厂商专用协议，可能需要指定 App 或 SDK。

Apple 在 [WWDC23 外接摄像头说明](https://developer.apple.com/videos/play/wwdc2023/10106/) 中明确说明：外接摄像头支持适用于具有 USB-C 接口的 iPad，iPadOS 17 的 AVCapture 可以使用 UVC 设备。视频还明确区分了 iPhone 可以使用相机偏好存储 API 与 iPad 的实际外接摄像头支持。

[AVCaptureDevice.DeviceType.external](https://developer.apple.com/documentation/avfoundation/avcapturedevice/devicetype-swift.struct/external) 标记 iOS/iPadOS 17 可用，并不等于所有 iPhone 上存在 UVC 采集驱动。该 API 也不是 iOS 15.6 的通用采集入口。越狱提供的权限不能替代缺少的视频驱动。

现有 AppleLive USB 直连是 Windows 作为 USB 主机，通过 usbmux 向手机发送编码后的音视频。摄像头直插手机则要求手机作为主机，枚举摄像头、协商格式并读取视频端点，是另一条底层通道。

libusb 上游 README 列出的现成支持平台未包括 iOS。后续找到了基于 Darwin 后端的旧版 iOS 移植路径，见下面“USB Host 实验实现”；仍缺少这台 iPhone 和目标 App 上的实际权限、采集验证。

## 下一步需要的设备信息

先提供一款实际用于测试的摄像头或采集卡型号、转接头型号，以及是否有手机 App 能显示它的画面。如果已有接收 App，还需要其名称和版本。具体样机用来确认协议和驱动边界，同协议设备可在此基础上扩展兼容范围。

后续兼容验证需要核实格式协商、断开和重新连接、后台释放与恢复、错误提示和来源切换。本次独立采集器通过 USB 直接读帧，不使用额外 AVCaptureSession，因此避开采集器自身被 AVCapture/BW 全局替换钩子再次处理的问题；与抖音同时运行的表现仍需实测。

如果只有普通 UVC 设备且手机没有可用驱动，当前已具备的可行路线是：摄像头/采集卡接 Windows → 在 OBS 中添加“视频采集设备” → AppleLive USB 或局域网发送到 iPhone。该路线不满足设备直接插手机的要求，不能作为直插功能交付。

## USB Host 实验实现

用户进一步明确采用“外置相机 → HDMI → USB UVC 采集卡 → OTG → 越狱 iPhone”，并要求把 USB Host 支持内置试用。继续检索后找到 [UVCDisplay](https://github.com/jamesy0ung/UVCDisplay)：该项目使用 libusb 的 Darwin 后端及 libuvc，在拥有额外权限的旧 iOS 进程中尝试读取 UVC。其应用代码锁定 MS2130，构建目标为 iOS16，不能直接证明 iPhone11/iOS15.6/抖音兼容。该项目应用代码没有明确许可，AppleLive 未包含其应用代码。

AppleLive 独立实现了采集封装，使用来自许可明确的上游 libusb/libuvc。第一版放在注入进程内；最新版本迁移到单独声明 USB 权限的采集服务，只有通过配对连接后才初始化 USB。悬浮窗提供“外接相机（测试）→ 配对采集服务、连接 / 重试、连接诊断、断开”。尝试枚举所有 UVC 设备，不按厂商 VID/PID 限定；优先 720p MJPEG，并在限制带宽的范围内尝试 YUY2/UYVY。转换后的自有 BGRA 帧进入现有镜像、旋转、比例、鱼眼和画面替换流程。

本阶段仅采集画面，没有实现采集卡 UAC 音频。内录开关保留原设置，开启时仍关闭手机麦克风，界面会明确提示外接模式暂无源音频。

**权限属于可执行程序，不能通过给 dylib 签名增加抖音权限。** 用户第一版诊断显示抖音没有声明两项 USB 权限、可见 IOUSBHostDevice 为零。枚举接口返回成功不表示找到设备；零设备也不能单独证明是权限、OTG 或供电问题。最新服务单独签名、以 mobile 用户运行，不更改抖音的权限，需在实机核实声明的权限是否生效以及设备是否可见。

服务安装包为 `AppleLive-UVC-Service-rootless.deb`，要求 Dopamine 等 rootless 越狱环境；仅安装 TrollStore 不能启动此服务。包内包含 `AppleLiveUVCHost`、桌面工具 `AppleLive USB` 和配套 `AppleLive.dylib`，无须从电脑分别传两个文件。

服务只监听手机自身的 `127.0.0.1:8767`，首次生成私有随机连接码，验证配对后才开始采集。原始 MJPEG/YUY2/UYVY 数据经手机内部连接传给插件，不经电脑或局域网、不增加编码。接收端每次完成一帧后才请求下一帧，服务只留最新一帧，避免慢接收积压。断开、切换来源或 App 进入后台时关闭连接并释放设备；界面仅在插件真正解码出画面后显示已接入。工具 App 的“服务已启动”只是进程初步检查，不等于采集卡可用。

## 真机试用步骤

1. 使用支持 USB 主机模式、可补充供电的 Lightning 相机转接器，按上述链路连接。普通充电转接头无法替代 OTG。
2. 相机先输出 720p 或 1080p、30fps 的 HDMI 信号，并给采集卡充足供电。
3. 用 Filza 安装 `AppleLive-UVC-Service-rootless.deb`，桌面打开 `AppleLive USB`。若图标没有出现，在 Dopamine 中刷新越狱应用后搜索。
4. 在工具 App 中点“导出配套手机插件”，保存到“文件”；用原来的注入器移除抖音的旧 AppleLive，再注入导出的 dylib。也可使用交付根目录的同名 dylib，两者内容一致。
5. 工具 App 显示服务已启动后点“复制连接码”。彻底退出后重新打开抖音，悬浮窗 → 外接相机（测试）→ 配对采集服务，粘贴后连接。配对会保存，下次直接点“连接 / 重试”。
6. 出现画面后检查方向、颜色和连续流畅度，再试断开、重连和切回其他信号源。
7. 没出画面时打开同一菜单中的“连接诊断 → 复制诊断”，提供日志以判断是服务连接、设备枚举、权限、协商还是解码失败。如果工具 App 一直显示服务未启动，先提供状态截图，不必反复注入插件。

本功能属于实验实现，尚无这台手机搭配实际采集卡的验证结果，不能作为全品牌兼容或量产验收结论。

## 服务版实机反馈

用户后续截图 `e04a3c486c817880bd7faed50d207686.jpg` 确认 iOS15.4.1 上 `AppleLiveUVCHost` 已启动，配对连接可返回服务诊断，两项 USB entitlement 可读取。当前仍无 `IOUSBHostDevice` 可见，UVC 返回 `-4`，失败发生在设备发现阶段，尚未到视频协商和解码。

用户确认 Lightning USB 相机转接器的独立供电口已接电源。不能据此断言转接器或供电有问题，也不能把可读取的权限声明等同于实际设备访问成功。代码核对发现诊断查询 `IOUSBHostDevice`，上游 libusb Darwin 后端查询 `IOUSBDevice`；参考项目也采用这一组合，目前缺少手机实际注册表证据，尚无依据直接更换底层匹配类。

下一步先用同一个转接器检查普通 USB 存储设备能否出现在系统“文件”中，结合转接器和采集卡型号区分 USB 主机连接识别与 UVC 特定访问问题。U 盘未出现也可能与文件系统等因素有关，不能作为硬件损坏的单独证据。本轮没有发布未经证据支持的替换二进制。
