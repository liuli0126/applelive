# 福煋推流插件：账号安全监控

本次把 `E:\2\pingbi\android-app` 的监控逻辑移植到 iOS 独立 dylib。Android 的 `MediaProjection` 和 ML Kit 不能直接链接到 iOS，因此 iOS 版本使用目标 App 自己的可见窗口截图和系统 Vision OCR。

## 入口

手机悬浮窗中新增「04 / 账号监控」区域。第一次点击「开始监控」会填写：

- 手机名称
- 直播账号或昵称
- 企业微信预警服务器的 HTTPS 地址：`https://服务器/mobile-alerts/<MOBILE_ALERT_TOKEN>`

之后点击同一个按钮即可开始或停止监控，信息保存在当前 App 的设置中。

## 识别规则

每约 1.5 秒取当前目标 App 的可见画面，在本机识别中文文字。只有同时满足以下条件才算目标弹窗：

- 标题包含「保障账号安全」
- 正文包含「进行验证」
- 内容包含「账号存在风险」或「人脸信息处理」
- 下方按钮包含「开始检测」，允许一次 OCR 字符误识别
- 文字的相对位置符合弹窗布局

首次 OCR 命中后立即提交一次提醒。弹窗持续存在时不会重复发送；弹窗消失后才重新布防。

## 网络与隐私

服务端协议沿用 `E:\2\pingbi\server-alert\MOBILE_ALERTS.md` 的 `security_verification` 事件。请求体不包含截图、原始 OCR、Cookie 或头像。网络错误、408、429 和 5xx 会使用同一个事件 ID 在监控仍运行时每 30 秒重试。

## 兼容边界

该实现需要 Vision、UIKit 和 HTTPS，当前 dylib 的 arm64 / arm64e 构建目标满足条件。它只能识别目标 App 能被窗口绘制出来的画面；系统保护层、黑屏或目标 App 被挂起时无法识别。需要在 iPhone 11 / iOS 15.6 + 抖音真机复测 OCR、后台切换和提醒服务。
